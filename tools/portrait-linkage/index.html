PORTRAIT · Local browser cryptography

Identifier encryption

Encrypt a fictitious identifier into a portable token, or decrypt a previously generated token using the same passphrase.

Prototype — synthetic identifiers only

This tool is published on a publicly accessible website and is not approved for real HiX patient numbers. Test only with identifiers beginning with TEST-. For clinical research use, first agree the linkage process with LUMC and preferably use Castor's own encrypted, searchable fields.

Local tool

No account · No data saved by this page

Use TEST- followed by 1–59 letters, digits, underscores or hyphens. Leading zeros are preserved.

The passphrase is not saved. A forgotten passphrase cannot be recovered by this prototype.

Copying may leave data in your system clipboard history.

Important limitations

The encryption uses browser Web Crypto (PBKDF2-SHA-256, 600,000 iterations, AES-256-GCM). The site code sends no data to a backend and does not use analytics, cookies or local storage.

Every encryption uses fresh randomness, so the same ID produces different tokens. Tokens cannot be searched by the original identifier without decrypting them. This tool does not connect to HiX or Castor and is not a replacement for an approved study code key.

Technical details and security considerations
  • Version 1 tokens have prefix PTR1.. They are compatible with the earlier offline prototype.
  • A 16-byte random salt and 12-byte random nonce are generated per encryption. AES-GCM authenticates the result.
  • The encrypted output may be copied manually. The decrypted result clears automatically after 30 seconds or when the page is hidden.
  • Website hosting, public source code, third-party browser extensions, a compromised device, clipboard managers or password loss are not solved by this client-side demonstration.
  • The full source is available in the public website repository. No real study identifiers belong in GitHub.
